# Découverte et recherche

## Objectif

Transformer la demande en problème compris, avec un périmètre et des inconnues identifiés. Pour un domaine méconnu, étudier ses règles avant de choisir un module ou une solution.

## Travail

| Action | Résultat |
|---|---|
| Lire la demande et le mandat | Objectif, acteurs, ressources et limites |
| Examiner le code et les documents existants | Capacités réellement présentes, dépendances et écarts |
| Relever les règles utilisateur | Identifiants et formulations source conservés |
| Étudier les inconnues utiles | Sources primaires, dates, options et limites |
| Comparer construire / réutiliser / intégrer | Avantages, coûts de maintien et conséquences |
| Définir le périmètre | Résultat attendu et exclusions justifiées |

Séparer constat, inférence et proposition. Rechercher une documentation actuelle pour les API et bibliothèques dont les garanties peuvent évoluer. Une recherche ne se limite pas à une liste de produits.

## Sortie

Compléter [RESEARCH.md](../templates/RESEARCH.md), puis le modèle de spécification adapté. Les questions réellement bloquantes sont explicitées ; les détails réversibles déjà couverts par le mandat peuvent être résolus avec jugement.

Pour Studio, commencer par le produit et les contrats utiles. Ne pas exiger l’étude de tout le catalogue avant chaque premier incrément.
