# Droits, lecture distante et confidentialité

L’acteur provient de la session Studio. Le site, la page, l’occurrence et la révision sont résolus dans son mandat. Le lecteur consulte les observations autorisées déjà enregistrées. Le gestionnaire peut modifier les champs simples, vérifier explicitement une source, associer, adopter ou détacher une référence. Protéger les commandes par CSRF et recontrôler les droits après une lecture distante ainsi que sous verrou avant toute écriture. Une révocation intervenue pendant l’échange rend le résultat inutilisable.

Le certificat de lecture identifie un service auprès d’une instance. Pour ce premier périmètre, le moteur résout exclusivement un type autorisé, publié, accessible publiquement et dans la racine configurée du site. Appliquer les restrictions héritées de Wagtail et toute restriction spécifique au type admis. La réponse pour une page inconnue, dépubliée, privée, d’un autre type ou d’un autre site est générique. Elle n’expose ni titre, ni corps, ni métadonnées de brouillon, ni identité de l’éditeur. Un changement de visibilité rend obsolète la précédente observation positive. La gestion des articles exige la session et les permissions propres à Wagtail. [Filtres de publication et visibilité dans Wagtail 7.4](https://docs.wagtail.org/en/stable-7.4.x/reference/pages/queryset_reference.html) · [Restrictions héritées](https://docs.wagtail.org/en/v7.4/advanced_topics/privacy.html)

La destination réseau provient du profil administré, la nouvelle route de lecture d’un contrat versionné. Le navigateur transmet un identifiant borné. Appliquer TLS mutuel, contrôle des deux identités, échéance totale, taille et schéma de réponse bornés, absence de redirection et d’URL fournie par l’utilisateur. Les GET/HEAD d’écran travaillent sur la base Studio. Une référence conservée et révoquée peut demeurer identifiable dans l’historique du site habilité. Les vues et journaux évitent de reproduire un ancien titre devenu sensible ou le diagnostic brut d’une instance. Purger ou masquer les métadonnées de présentation lors d’une indisponibilité, sans modifier le repère historique.

Les valeurs locales utilisent les validateurs de la définition et la résolution média côté serveur. Échapper les textes, laisser les liens inertes dans le canvas et rendre les médias depuis leur circuit autorisé. L’adresse d’administration, si elle est proposée, dépend d’une configuration navigateur contrôlée ; le domaine de la fiche, le port d’exemple d’un poste et l’origine mTLS ne déterminent pas cette adresse. Ne transmettre aucun jeton de service dans le lien. [Raccordement](../ARCH-002/SECURITY.md) · [Sécurité du canvas](../FEAT-003-05/SECURITY.md)

Pour la recette, utiliser deux sites fictifs, des comptes Wagtail distincts et une source dont l’accès peut être révoqué. Vérifier les données visibles dans le HTML, les réponses et les preuves. Tester les courses d’observation, les doubles soumissions, le changement de profil et les tentatives de copie d’une référence privée entre sites. Observer les appels moteur et comparer les historiques afin de distinguer les publications Wagtail réalisées exprès par le rédacteur des actions déclenchées par Studio.
